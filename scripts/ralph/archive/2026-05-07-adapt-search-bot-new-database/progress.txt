## 2026-05-06 14:00 - US-006
- Created `backend/scripts/check_boss_urls.py` — CDP browser checker for BOSS直聘 job URL validity
- Connects to Chrome via patchright CDP at `http://localhost:9222`
- Queries `source='BOSS直聘'` + `is_active=True` jobs from DB
- Opens each URL in browser, waits 2.5s for render, checks page text for "职位已关闭"
- Closed jobs: `is_active=False` + `status='expired'`; normal jobs: keep `is_active=True`
- Both cases update `last_checked_at` timestamp
- Random 3-5s delay between URL checks for anti-detection
- Supports `--limit N` and `--dry-run` (detect only, no DB writes)
- Batch DB update after all checks complete (single commit)
- ruff check passes

**Learnings:**
- Script uses `sync_playwright` for CDP + `asyncio.new_event_loop()` for async DB operations, consistent with other scripts like `populate_cdp2.py`
- `page.content()` captures full rendered HTML/text, sufficient for detecting "职位已关闭" text indicator
- `Page.goto(wait_until="domcontentloaded")` with 2.5s extra sleep gives JS time to render dynamic content
- Error handling per-URL prevents one bad URL from crashing the entire batch

## 2026-05-06 14:30 - US-007
- Added `_apply_recommendation_filters(jobs, user_cities, min_salary_threshold)` function to `chat_service.py`
- Three-tier cascade: strict match (city+salary) → city-only fallback → full return with hint
- City filtering uses `normalize_city()` on `JobItem.city` field (since JobItem has no city_normalized)
- Salary threshold: `MIN_SALARY_THRESHOLD = 10000` (月薪最低阈值)
- Integrated into `search_jobs()` post-processing, replacing manual `_sort_jobs()` call
- Fallback message appended to ChatResponse.message for user transparency
- ruff check passes

**Learnings:**
- JobItem schema has `city` (raw) but not `city_normalized` — must normalize at filter time via `normalize_city(job.city)`
- `_sort_jobs()` is reused inside the filter function (not duplicated) — sorts by salary_max desc, puts 0-salary jobs last
- When user doesn't specify cities, city filtering is skipped entirely (keeps all jobs for salary-only filtering)
- The filter function returns `tuple[list[JobItem], str]` — caller composes the final message
